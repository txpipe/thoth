# The claim carries byte value slots

Status: accepted, amended by [ADR 0015](0015-attestors-sign-the-nullifier.md): the signed message no longer carries the byte values or their flags. They reach it through the nullifier. Also amended by the shape note below (issue #313): a byte slot travels as one `Bytes<32>` with one presence flag, and the message signs `V` and `W`.

The claim carries `W` fixed-width byte value slots (`Bytes<32>`) alongside its `V` numeric `Uint<64>` slots, addressed by one `present` mask of length `V+W`: numeric slots first, byte slots after. A byte value is exactly its 32 bytes; no length travels in the claim, and a policy's parse rule canonicalizes a source's string into the slot, zero-padding shorter values. A hash was rejected: it is lossy, and with no SHA-256 in the pinned stdlib a circuit could never recompute it from the source. `W = 0` is the numeric-only layout.

Shape note (implemented, issue #313): the contract's `Claim` and its observation identity carry the byte slots as `byteValues: Vector<W, Bytes<32>>` with one `bytePresent` flag per slot, and the module's byte parameter is the slot count `#W`. The `present` mask of the kind-facing claim splits into `present` (the `V` numeric flags) and `bytePresent` (the `W` byte flags), because the contract types the two vectors differently. An absent byte slot is all zero bytes, as an absent numeric slot is zero, and the contract rejects any other.

Each byte value used to travel as two `Bytes<16>` halves with a flag per half (`#B = 2W`), a shape that kept the old flat message cheap: each half was one `Uint<128>` field. Once attestors sign the nullifier ([ADR 0015](0015-attestors-sign-the-nullifier.md)), nothing needs the halves, and they cost a predicate: reassembling a value from its halves to compare it with a `Bytes<32>` took about 8,600 rows, while comparing two `Bytes<32>` takes about 170. Whole values brought `openAndReadBytes` from `k = 15` to `k = 14`. They also drop two traps of the halves: the two flags of one value could disagree, and an odd `#B` compiled and then rejected every claim.

The observation identity hashes a plain concatenation, 136 + 9V + 33W bytes, so its length does not fix the split between `V` and `W` (`V = 11, W = 0` and `V = 0, W = 3` share a length). The message signs `V` and `W`, which the contract rebuilds from its own `#V` and `#W`, so honest signatures over one layout cannot verify against another. The full layout is in the `attestation.compact` header and the docs/DESIGN.md table.

Canonicalization note: the string→slot mapping is not injective — trailing NUL bytes collapse into the zero padding and unpaired surrogates normalize to U+FFFD — so a byte slot's identity is the padded 32 bytes, not the source string. ADR 0010's `length` pin keeps zero padding from merging values of different lengths. Fixed width is what lets a circuit compare values without a length, and a hash was already rejected as lossy.

Privacy note (superseded by [ADR 0012](0012-nullifier-hashes-a-secret-attestor-derived-salt.md), which salts the nullifier): the replay nullifier (ADR 0006) is a public, unsalted hash of the observation, and every other input to it is public or guessable — the transaction discloses the policy hash and the window, the app id is the app's constant, and a fixed endpoint fixes the subject hash. Anyone can therefore confirm a guessed byte value by recomputing the nullifier. Numeric values were always exposed this way, but byte slots carry identifiers, which are easy to enumerate. ADR 0006 rules out client randomness in the nullifier, so this is accepted: an app whose byte values must stay secret should not rely on the claim keeping them hidden.
